Each team hands files to the next: research notes → blueprint → base code → screens → reviews → fixes.

  • Own your files. Every agent had a list of files it could change. Nobody else could touch them.
  • Read before you write. A critic read all five research notes and found where they disagreed. That happened before any code.
  • Look, then fix. Agents took screenshots in dark and light and looked at them. They did not trust code alone.
  • Reviewers only report. They could not edit the code. One job to find faults, a different job to fix them.
  • Two at a time. The machine has 4 CPUs. The tool ran at most two agents of one team together.
  • Design system stays pristine. Nobody edited the Springboard files. Fixes went around them.

    Problems caught before they shipped

    The critic agent joined the five research notes and tried to build the pieces together. It found these. Fixing them early was cheap.

    • Blank screen offlineThe design system loads fonts from the internet. On a slow venue network the page stayed blank for 8 seconds or more. The team made an offline copy of the styles.
    • Two datasetsTwo research agents each made a different sample council with different numbers. One was picked. The other was kept as reference only.
    • Two app shellsTwo agents built two versions of the page frame. The one checked pixel by pixel against the template won.
    • Cards that did not add upFour cards added up to £6.2m under a £6.1m headline. The page now shows the exact sum under the cards.
    • Keyboard bugIn a table, pressing Enter on a link inside a row opened the row instead. Mouse clicks worked, so it was easy to miss.
    • Wrong words for a demoOne planned line said "public data" but the data is made up. Another showed an internal risk to customers. Both were reworded.

    • Most at once3 agents ran at the same time. The machine has 4 CPUs, so each team runs two agents at a time.
    • Screenshots savedAt least 2,005 pictures of the app, in dark and light, at four screen sizes. Agents looked at them.
    • Tests536 browser checks and 14,987 engine checks at the last full run. No check failed.
    • ReviewsFour review reports (look, function, access, spec) found 1 blocker (an old offline file) and a handful of major issues. The clear ones were fixed. The rest are listed in docs/review.
    • Stopped on purposeThe review team was stopped early to save usage. Two of six reviewers had not finished. The build was then checked with the existing tests, once.

    How to read these numbers

    • Agent hours add up every agent's run time. Agents ran at the same time, so real hours are smaller.
    • Tool calls and steps come from the logs of each agent. Tokens come from the workflow tool for finished teams.
    • The main session also did work. It is counted on its own, not in the agent totals.
    • The app uses made-up data. The council and suppliers are fictional. This page does not change that.
    • Only Chromium was tested. Safari and Firefox were not.
    • Tokens for the stopped review team are not counted, because the tool only reports tokens when a team finishes.
    • Agent hours include the stopped review team up to the moment it stopped.
