## What changed against the research reference (no golden number moved)

Field-by-field comparison against `research/work/ref/engine.mjs` over six scenarios (default, confirm Larchmont, explain highways, 8% rate, 80% and 90% near-cap): every indicative GBP, rank, total, severity, basis, action date, band, spend, cap and uplift figure is identical. The only differences are added fields, plus these deliberate changes: `F-C-017-nearCap` (a contract-value cap on the GBP 0 watch list) gets the estimate labels and confidence `high` to `medium`; in the confirm scenario `F-C-009-overCap` confidence goes `low` to `high` and `derived.C-009.spend.minMatchScore` 0.73 to 1 (change 6 below).

1. **capState (decision 9).** `derived[id].cap` gains `source` and `capState`: `'over' | 'above_estimate' | 'near' | 'ok' | 'none'`. `state` is unchanged. `above_estimate` = spend above a cap whose `cap.source === 'contract_value'`. Such flags keep the same GBP and the same `type: 'overCap'`, and get `capState`, `capSource`, severity `medium` (a stated-maximum breach stays `high`), confidence one step lower (`confidenceSteppedDown: true`) and estimate wording in the breakdown. Labels: `capStateLabel(cap)` gives "Over cap", "Above contract value (estimate)", "Close to cap", "Close to contract value (estimate)", "Within cap", "Cannot test"; `flagTypeLabel(flag)` gives "Above contract value (estimate)" for such a flag.
2. **contract.source** `'find_a_tender' | 'register_pdf'`. Rule: starts on or after 24 Feb 2025 and total value over GBP 5m. None qualifies, so all 24 are `register_pdf`. `sourceLabel(contract)` gives "Council contracts register, PDF" or "Find a Tender notice and contract".
3. **Data-basis facts** on `data.council`: `spendVatBasis`, `contractValueVatBasis`, `spendFileCount` (54), `spendWindowLabel` ("Sample payments to 30 September 2026"). Words: `COPY.vatNote`, `COPY.dataWindowNote(council)`.
4. **Contract documents are real pages** (schema below). The maximum-not-found extraction on contract-value contracts moved to `Contract Particulars, item 10` (was item 9, which clashed with the total value item). Quotes are otherwise unchanged. `noticePeriod` and `autoRenewal` share one block on the page.
5. **Engine additions:** `confidence` per flag is now accompanied by `confidenceScore` and `confidenceField` (the weakest input: an extraction field key or `'supplierMatch'`); `totals` gains `countByType`, `excludedGBP`, `excludedCount`; `derived[id]` gains `usedEndDate`, `status` (`'live'|'ended'`), `latestEndDate`, `nextReviewDate`, `flagIds`; `derived[id].spend` gains `coverageFrom`; `coverage` gains `noContractGBP`, `awaitingReviewGBP`; new `buildRadar()`; annual-cap near-cap breakdown is now correct; `isCounted(flag)`, `isExcluded(flag)` exported.
6. **Deliberate refinement:** a supplier match you confirm counts as certain (score 1.0) for flag confidence, so a flag does not say "Needs review: supplier match" about a link you just confirmed. The 0.73 similarity is still shown on the matches tab. Golden amounts are unaffected.

## Contract document page schema (build the Source viewer on this)

`estate.data.documents[contract.documentId]`:

```
{ id: 'DOC-C-005', contractId, title: 'Highways reactive maintenance and minor works: agreement', pageCount: 70, isIllustrative: true,
  pages: { [pageNumber]: Block[] } }       // only pages that hold an extracted answer exist; any other page is the "This page isn't in the sample." state
```

`Block` (ordered array per page):

| kind | fields | meaning |
|---|---|---|
| `header` | `text` | running header, exactly `Marchbank Borough Council | <title> | Page 23 of 70` |
| `heading` | `num?`, `text` | `{num:'14', text:'Charges and Maximum Contract Value'}` renders "14. Charges ..."; `{num:'Schedule 3', text:'Schedule of rates'}` renders "Schedule 3: ..."; Particulars has no `num` |
| `clause` | `num`, `title?`, `text`, `clauseRef?`, `extractionIds?` | numbered clause, schedule paragraph or table (`'14.3'`, `'2.1'`, `'Table 1'`); `title` is the bold lead-in |
| `item` | `num`, `text`, `clauseRef?`, `extractionIds?` | one row of the Contract Particulars table |
| `footer` | `text` | `Execution version | Contract ref C-005 | <supplier>` |

- A block is **cited** when it has `extractionIds`. Its `text` equals the quote of every extraction it lists; `clauseRef` is the citation ("Clause 14.3"). Highlight only the block where `extractionIds.includes(currentExtractionId)`: the Particulars page has four cited items and the others must not be highlighted when you view one of them.
- Every cited page has 1 header, 1 heading, **4 to 6 non-cited neighbours** (always 6 on C-005, C-001 and C-004), the cited block(s), 1 footer.
- Text is numerically consistent with the contract fields (80% alert amount, last date for notice, latest end date, payment days, invoicing cadence). C-005: Particulars item 10 carries the "budgeting purposes only" sentence, page 23 has clause 14.3 (the cited maximum), 14.4 (80% alert, GBP 4,000,000) and 14.5 and 14.7 (agreed in writing).
- Page numbers: Particulars 3, extension 9, payment 16, cap 19, termination 27, notice 28, exit fees 29, rate card 39, price review 42, service credits 47, each plus the contract's 0 to 4 offset. The cap clause has its own page only when a maximum is stated (11 contracts); otherwise `maximumValue` cites Particulars item 10. Golden: C-005 clause 14.3 on page 23 of 70; C-001 notice page 28; C-004 price review page 45.
- Label to show beside it: `COPY.illustrativeLabel` ("Illustrative contract text written for this demo, not a real document.").
- Reference renderer: `src/dev/A2-page.jsx` (about 30 lines).

## API

```js
import { EstateProvider, useEstate, computeEstate, paymentsFor, handcheckSummary, ASSUMPTION_OPTIONS, TRIAGE_STATUSES } from '../lib/estate.js';
const { estate, state, actions, storage } = useEstate();   // throws a clear error outside <EstateProvider>
```

`estate` (full list in the JSDoc at the top of `estate.js`): `data, opts, asOf, council, matches (Map), matchList, attributed, flags, ranked, watch, flagsById, derived, summaries, totals, coverage, radar, capRows, contractsById, extractionsById, extractionsByContract, paymentsByContract`.

- `estate.totals` = `{ totalGBP, contractCount, byType, countByType, excludedGBP, excludedCount }` (counted flags only).
- `estate.radar` = `{ boundaries: {m3,m6,m12}, groups: { passed, ended, m3, m6, m12, later, history }, attention[] }`; each group `{ key, count, annualGBP, totalGBP, items: [{ contractId, band, deadline, usedEndDate, endDate, annualValueGBP, totalValueGBP, afterEndGBP, flagId }] }`, items by notice deadline ascending. `attention` is the "Needs attention now" list in the order C-001, C-016, C-007.
- `estate.capRows` = testable caps by utilisation descending: `[{ contractId, ...derived.cap }]`.
- `paymentsFor(estate, contractId)` = `{ all, inTerm, afterEnd, totalGBP, inTermGBP, afterEndGBP }`; `totalGBP` equals `derived[id].spend.toDate` to the penny (R38).
- `state` = `{ triage, decisions, assumptions, handcheck, feedback }`; `actions` = `setTriage(flagId, status|null)`, `setDecision(rawName, 'confirm'|'reject'|null)`, `setAssumption('renewalRate'|'nearCapThreshold', value|null)`, `setHandcheck(extractionId, 'correct'|'incorrect'|null)`, `addFeedback({ answer: 'yes'|'maybe'|'no', comment })` returning `{ ok:true }` or `{ ok:false, reason:'no_answer'|'storage_blocked' }`, `resetAll()` (clears the five keys, keeps `kontor-theme`).
- `storage.blocked` is true once any write could not reach localStorage. Everything keeps working for the session. Persistence goes through A1's `src/lib/storage.js` (same five keys); corrupt or wrong-shaped JSON is ignored per key.
