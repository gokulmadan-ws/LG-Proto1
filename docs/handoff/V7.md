## Judgement calls worth knowing

- **The Menu is not the kit `Menu`.** The kit `Menu` renders a `div role="menu"` straight into `<body>`, which fails axe `region` (content outside every landmark); A1's stub note and foundation-status say the popover must stay inside `<nav aria-label="Menu">`. `MenuPopover` therefore uses the kit `Popover` (placement, outside press, Escape, layer order) with the kit's menu classes and the same key handling as the kit `Menu`. If A3 later lets `Menu` take a wrapper or a landmark role, this file can go back to `Menu`.
- **Evidence h1 is "Why this matters"** (A2's `COPY.pages.evidence`, the Menu label and the Overview strip heading), and `usePageTitle` makes the document title "Why this matters | Kontor financial layer"; `routes.js` still says "Evidence". The spec's word "Evidence" is the eyebrow. Say so if you want them the same.
- **Feedback closes after a save** (the stub contract said so); the entry shows in the saved list the next time it opens. The form always starts empty.
- **Settings uses `Segmented`, not radio buttons,** so the two three-way choices fit on one line and the drawer fits 1440x900 without scrolling (at 1366x768 it scrolls inside the drawer). Each segment is `role="radio"` in a `radiogroup`, with Arrow keys.
- **`ui.confirm` for the reset,** not a dialog of my own: it is the kit `ConfirmDialog`, Cancel first, stacked above the drawer.
- **Evidence feature links:** the spec's "Kontor feature it supports" text is shown word for word and the feature names inside it are the links (matched ignoring case, so "Cap vs actual spend, clause checks" stays as written). A2's link table sends Edinburgh to `#/spend/no-contract` and Windsor & Maidenhead to `#/contracts` for the same words ("Contract register built from documents"); I kept that, and every link has an `aria-label` that names its case. A2's `#/method` for the Sefton caveat link becomes `#/method?s=indicative` (V3's section id).
- **Tables turn into cards under 700px** (`ResponsiveTable`, a `matchMedia` switch): the status table, the Stage 1 and 2 table, the illustrative table and the Evidence table. Above 700px they are the kit `DataTable`.
- **Inline source links on the Roadmap** keep the spec's link text and each says "(opens in a new tab)" in visible words (no arrow glyph: the words already say it, and the sentences stay quiet).
- **The Stage 1 and Stage 2 comparison table** is on the page because requirements section 9 item 2 lists it, although the task text did not name it.

- Chromium only (the kit and charts use `color-mix` and container queries; `matchMedia` is used for the phone cards).
- No real screen reader run. Names, roles and live regions were checked with axe and by reading the accessibility tree through Playwright locators (`getByRole`).
- **The Settings gear is hidden under 700px** (A1), so the Settings drawer cannot be opened on a phone; the Menu has no Settings item (the blueprint lists five items). Not changed.
- The Settings drawer scrolls inside itself at 1366x768 (the Reset button is below the fold there).
- Dialogs and drawers animate in only (kit).
- Feedback timestamps use the browser's local time zone; `feedbackText` prints the date part of the stored UTC timestamp, so a late-evening entry can copy as the next day in a time zone behind UTC.
- The "In this sample all 24 contracts come from the council contracts register (PDF)" line is built from `contract.source`; if a future dataset marks a contract `find_a_tender` it switches to "N of 24".
- Hand-checked on screen against the golden numbers: headline `£6.1m` and the sum line with the default rate, `£6.8m` and `£6,790,538` at 8%, `£5.7m` and `£5,715,038` at 3%, the 15 contracts, the Demo guide's `£8.4m` against `£5.0m` and clause 14.3, page 23. Not checked: any page I do not own.
