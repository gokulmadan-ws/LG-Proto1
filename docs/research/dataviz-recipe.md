# Data-visualisation recipe: Kontor financial layer (Stage 1, single council)

Audience: the BUILD agent. Everything here is implemented, tested and screenshotted; lift the code, do not re-research.
Author scope: the visual layer only (charts, figures, colour, tooltips, accessibility). The engine, data and routing are other agents' work; this file shows exactly how engine output maps onto chart props.

Method: the `dataviz` skill (form heuristic, four colour jobs, six checks with the runnable validator, mark specs, interaction rules), applied to Springboard 2.0 tokens. Springboard ships no chart components, so the library is hand-rolled React + CSS (rows, bars, meters) and SVG (the one line chart).

### 0.2 Install in six steps

1. Copy `work/charts/*` to `src/components/charts/`. Nothing in it imports the design-system bundle; it needs only the React global that `scripts/build.mjs` already provides, Font Awesome (already linked) and the Springboard CSS variables (already linked).
2. In `src/main.jsx` add `import * as C from './components/charts/index.js';` (the index imports `charts.css`, so esbuild bundles the CSS into `dist/app.css`; no other CSS import is needed).
3. Wrap every chart in a Springboard `<Card padding={24}>` and a `<ChartFigure>` (title, description, legend, table twin, footnote).
4. Feed props through `adapters.js` from the engine output (`buildFlags`, `radarBand`, `capStatus`, `upliftCheck`, `coverage`). The charts never compute a business rule.
5. Add the global focus rule from 2.5 item 4 (the Springboard Button has no focus ring and cannot be fixed without `!important`).
6. Do not use the Springboard `Badge` for flag types or states (its tone colours fail WCAG AA); use `FlagBadge`, `FlagChip` and the `kviz-pill` class (2.5 item 1).

## 1. Decisions at a glance

| # | Visual | Requirement | Form chosen | Component(s) | Why this form |
|---|---|---|---|---|---|
| a | Headline | R16, R17 | Hero sentence (a real `<h1>`) + one 100% stacked bar by flag type + four basis cards | `HeadlineTile`, `StackedBar` | One number leads, so it is a figure not a chart. The bar is stacked only because the four parts sum to the whole. Cards carry the basis (units differ), so the sum is never misread. |
| b | Renewal radar (page) | R31 to R36 | **Time-axis lanes grouped by band**, each contract a "time left to act" bar, a diamond at the notice deadline, a tinted notice-period band and a tick at contract end; value as a number plus a shared-scale data bar | `RadarLanes` | Beats three bucketed lists (no sense of time or urgency) and a bubble timeline (area is unreadable, same-date bubbles collide, hit targets are small). Evaluation in 4.2. |
| b | Renewal radar (Overview) | R18 | Strip: three band cells whose widths follow the time scale (25/25/50%), diamonds underneath, "Needs attention now" pill | `RadarStrip` | The Overview needs the radar in one row at 1440x900 (R78). |
| c | Cap vs spend (page) | R37 | Ranked **bullet bars** on one shared axis (% of each contract's cap); amber 85 to 100% zone, cap tick, red fill with a hatched overflow | `BulletList` | Small multiples on one axis sort by utilisation and make "over" a geometric fact (the bar crosses the tick), not just a colour. |
| c | Cap vs spend (annual cap) | R40, R42 | Columns per contract year against a per-year cap line; over-cap years hatched above the line; running year outlined | `YearBars` | An annual cap is tested per contract year, so a cumulative line would be wrong. |
| c | Cap vs spend (one contract) | demo step 3, "Guildford moment" | Cumulative spend line vs horizontal cap line; line turns red at the crossing; crossing annotated | `CumulativeLine` | A single series over time is a line; the cap is a horizontal reference. |
| d | Spend-to-contract coverage | R19, R46 | One 100% bar (blue matched, hatched amber unmatched) + ranked unmatched suppliers; on the Overview a one-ratio **meter** | `CoverageBlock`, `CoverageMeter` | Part-to-whole of two parts is a bar, a single ratio is a meter; never a pie. |
| e | Uplift check | R60 (stretch) | **Dumbbell**: tick = index cap, dot = change in payments, connector = the gap; three states | `Dumbbell` | Cap vs actual per supplier is a before/after pair per row. Reuses the bullet "limit tick" language. |
| f | Opportunities list | R23 to R30 | Ranked horizontal bars of indicative GBP, flag glyph chip, basis line, confidence dots, clause link | `OpportunityList`, `BarList` | Rank is the point; bars give magnitude, the direct label at the tip gives the number. |

Cross-cutting: every chart has a `Show table` twin, tooltips on hover AND keyboard focus, a full-sentence `aria-label` on the focusable mark, and shape/pattern/words in addition to colour.

Rules that follow from the dataviz skill and are baked into the code:

* **Text never wears the series colour.** Values and labels use `--viz-ink`/`--viz-ink-2`. The `-text` tokens exist only for words and glyphs that sit beside a mark (status pill, flag chip glyph, tooltip glyph); they are darker on light and lighter on dark so they clear 4.5:1 on the surface and on a 12% tint of their own mark.
* **Colour follows the entity, never its rank.** Filtering the opportunities list to "Spend over cap" leaves the bars red (asserted by test).
* **Status colours are a fixed scale with reserved meaning**, always with a glyph and words.
* **One axis, no dual axes**, thin marks, hairline solid grid, a 2px surface gap between touching marks, a 2px surface ring around dots and diamonds.
* **Texture is a backup channel**, 45 degrees only (an SVG `<pattern>`, so the UI has no CSS gradients).

**Fixed stack order for the headline bar (important):** over cap | price increase | close to cap | renewal. It puts red beside purple, purple beside amber, amber beside blue. Every adjacent pair is at least 30 dE (OKLab x100) under protanopia and deuteranopia. Blue and purple collapse under deuteranopia (dE 1.6 dark, 4.0 light), so they must never touch; any reordering that puts them adjacent fails. The four basis cards use the requirements doc's reading order (over cap, close to cap, renewals, price increases) because each card is labelled with glyph and words and the colours never touch.

Note on dark amber: the validator's lightness band is a rule for categorical identity colours. Amber here is a **state** colour (close, no contract). The skill's own dark status warning (#fab219, L 0.811) and Springboard's `--warning` (#CB8F09, L 0.691) fail the same band. The brighter #D9A125 keeps red/amber at dE 15.5, so it is the right trade; it is recorded here so nobody "fixes" it.

Rejected orders: renewal first (valid but the story reads badly), and any order with blue next to purple (hard CVD FAIL).

### 2.5 Springboard gotchas that affect charts (each one was verified)

1. **`<Badge>` tones fail AA.** Soft badge text is the tone colour on a 16% tint of itself: blue 3.17 / 3.98, red 3.26 / 4.11, purple 2.84 / 4.01, green 4.23 / 2.63, amber 4.77 / 2.33 (dark / light). Use `FlagBadge` or the `kviz-pill` class (`style="--c: <mark colour>; color: <-text token>"`, 12% tint, 22px high). If a reviewer insists on `<Badge>`, override both colour and tint: `<Badge tone="red" style={{ color: 'var(--viz-danger-text)', background: 'color-mix(in srgb, var(--viz-danger) 12%, transparent)' }}>` (Badge spreads `style` last, so this works).
2. **Semantic `--warning` (#CB8F09) is 2.5 to 2.8:1 on every light surface** and `--success` (#3EA251) is 2.9 to 3.2:1; neither passes 3:1 as a light-mode mark. Use `--viz-warning` (resolves to `--yellow-600-2` in light). `<Progress tone="amber">` has the same problem in light mode; do not use it for caps (use `BulletList`/`CoverageMeter`).
3. **`--fg-3` fails AA for text on every surface** (3.75 dark card, 2.97 light white). Chart axis and label text uses `--fg-2` (`--viz-ink-2`). `--link` (#0969DA) is 3.30:1 on the dark card: for text links on dark use `--viz-accent-text` (`.kviz-textlink` does).
4. **The DS `Button` and `Tabs` set `outline: none` inline, so they have no keyboard focus ring and a normal CSS rule cannot restore it.** Verified in the browser: a plain `:focus-visible` rule changes nothing; with `!important` it renders a 2px ring. Add once to `src/styles/app.css`:
   ```css
   :focus-visible { outline: 2px solid var(--viz-focus) !important; outline-offset: 2px !important; }
   ```
   (Chart marks already ship their own rings; this fixes the DS controls and meets R69.)
5. **The DS `Tooltip` is a hover wrapper with `position: absolute` and `white-space: nowrap`**, and the DS `Card` has `overflow: hidden`, so a DS tooltip near a card edge is clipped and cannot hold a table of values. Charts use `ChartTip` (portal, `position: fixed`) instead.
6. **DS button heights are 28, 36 and 40px; the touch target rule is 44px.** Compact controls use a `::after { inset: -8px -4px }` hit area (`.kviz-btn`, `.kviz-seg`, `.hx-chipbtn` in the harness). Rows are at least 52px tall.
7. **`--font-display` ('Inter Display') ships Regular, Medium, SemiBold and Bold only.** The hero figure uses 600, which exists. Proportional figures for large numbers; `tabular-nums` only inside columns and axis ticks.
8. **fig-tokens `--border-2` is redefined by `colors_and_type.css`** (checked in the browser: `--viz-axis` resolves to #3E3F47 dark, #C1C1CC light, as documented).
9. **The App Shell template is dark-only** (hard-coded #08090B, #3E3F47, #1A1B22). The light variant is the build agent's decision; the chart tokens were validated on the three light surfaces listed in 2.4 (white, #F9FAFB, #F2F3F7), so use any of them.

### 3.2 Where thresholds come from

The charts take bands, states and flags from the engine and never re-derive them: `radarBand` (right-closed windows: a deadline exactly 3 months out is "Next 3 months"), `capStatus` (over above 100%, near from 85% to 100% inclusive), `upliftCheck` (flagged when the change exceeds the cap by more than 1 point AND the excess is at least £10,000). The only geometry the charts compute is position: `monthsBetween` turns a date into a fraction of the 12-month axis (exact at whole-month anchors: 6 Oct to 6 Jan is exactly 3).

### 4.2 (b) Renewal radar

#### Option evaluation (what a demo audience reads at a glance)

| Criterion | A. Time-axis lanes grouped by band (**chosen**) | B. Three bucketed lists | C. Bubble timeline |
|---|---|---|---|
| Reads "what is coming and how soon" | Yes: x position is time, the diamond is the deadline, group headers give the three buckets the spec names | Only by reading dates; no urgency gradient | Yes for time, but overlapping bubbles on the same date (3 deadlines fall on 28 or 31 Oct) hide each other |

| Keyboard and screen reader | Real rows, real links, real text | Same | Many tiny focus targets |

| Build cost | Medium (done) | Low | High |

### 5.4 Tooltip implementation notes (full code in Appendix A, `Tip.jsx`)

* `useChartTip()` holds `{ rect, px, content }`. `bindPointer(content)` goes on the whole row (hover; follows the pointer's x, clamped to the row), `bindFocus(content, rowSelector)` on the focusable link (focus; anchors to the row), `bind(content)` does both for a self-contained mark (a stack segment).
* `ChartTip` measures the tooltip after render (`useLayoutEffect`), centres it above the anchor, clamps to the viewport (8px margins) and flips below when there is no room above. It renders into `document.body` with `position: fixed`, so no ancestor `overflow: hidden` can clip it.
* Esc, scroll and a pointer-down outside any `[data-kviz-mark]` or `.kviz-tip` close it; leaving a mark closes it after 160ms unless the pointer enters the tooltip (hoverable). Touch: a tap shows it, a tap elsewhere hides it (no leave-timer for `pointerType === 'touch'`).
* `data-kviz-mark` marks the focusable elements; `useArrowNav` uses the same attribute to move focus between rows.

## 9. Risks and gaps

1. **Browser floor.** The charts use CSS container queries (Chrome 105, Safari 16, Firefox 110) and `color-mix()` (Chrome 111, Safari 16.2, Firefox 113). Fine for a demo laptop; there is no fallback for older browsers.
2. **Springboard defaults that will bite if used instead of the chart tokens:** Badge tones (AA fail), `--warning` and `--success` as light marks, `--fg-3` text, `--link` on dark, DS Button focus ring, DS Progress amber in light, DS Tooltip clipping (2.5).
3. **Amber in dark mode fails the validator's categorical lightness band** by design (state colour); do not "fix" it with a duller amber because red and amber rows then collide under deuteranopia (2.3).
4. **Blue and purple are not separable by colour for deuteranopes.** Every use of the flag colours pairs glyph and words; never remove the glyph from a chip or the words from a pill.
5. **Hatch contrast on light surfaces.** Amber stripes on the light `bg-2` surface (#F2F3F7) are 2.9:1 (the amber mark itself is 3.1:1 there). Keep amber hatch on white or `bg-1` cards (3.0 to 3.3:1); the stat blocks and labels carry the meaning regardless (relief rule).
6. **A long list is long.** 24 cap rows are about 1,900px tall; use `limit={12}` plus "Show all". The opportunities list shows 10 by default.
7. **Opportunity scale.** One large flag (£3.4m) makes the rest short bars. Honest and labelled; do not break the axis.
8. **Wording is placeholder where the copy deck should win.** `defaultReason` sentences, the clause label and the chart-chrome strings in 7.5 are mine; the requirements doc 7.5 and 7.6 own the final text.
9. **Clause pages in the harness are fake** (`clauseFor` hashes the contract id). Wire the real provenance records.
10. **Row component conventions the app must keep:** one primary link per row, extras only inside the `extra` slot, never wrap a row in another link or button.
11. **Radar months vs engine days.** Band membership comes from the engine (right-closed month boundaries); x positions use calendar-month fractions. They agree at the boundaries (a deadline exactly 3 months out is in "Next 3 months" and sits on the 25% hairline).
12. **Partial coverage.** Spend figures for a contract that began before the spend files are labelled "At least" in the row and the tooltip. The detail line starts at 0 on the later of the contract start and `council.spendDataFrom` (`cumulativeSeries(attributed, contract, spendFrom)`), so it never invents a ramp; say so in the page copy (R39).
13. **No unit tests for components.** Coverage is the Playwright script; port its assertions into `tests/` if the project adds a test runner.
14. **Two sibling documents disagree on the council name** (requirements: Marchbank; domain brief: Brindleford). The charts are name-agnostic.

// src/components/charts/format.js
// Formatting + date helpers shared by every chart. Pure functions, no React.
// Dates are handled as UTC midnight so the as-of date never drifts with the viewer's timezone.

export const AS_OF = '2026-10-06';            // fixed demo as-of date; never Date.now()
export const DAY = 86400000;
const MONTHS = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec'];
const MONTHS_LONG = ['January', 'February', 'March', 'April', 'May', 'June', 'July', 'August', 'September', 'October', 'November', 'December'];
const MINUS = '−';                         // proper minus sign for negatives

/* ---------------------------------------------------------------- dates */
export const toDate = (v) =>
  v instanceof Date ? v : new Date(/^\d{4}-\d{2}-\d{2}$/.test(v) ? v + 'T00:00:00Z' : v);
export const iso = (d) => toDate(d).toISOString().slice(0, 10);

/** '6 Oct 2026' (fixed month names: Intl en-GB prints "Sept", the spec wants "Sep") */
export const fmtDate = (v) => { const d = toDate(v); return `${d.getUTCDate()} ${MONTHS[d.getUTCMonth()]} ${d.getUTCFullYear()}`; };
/** '6 October 2026' for prose */
export const fmtDateLong = (v) => { const d = toDate(v); return `${d.getUTCDate()} ${MONTHS_LONG[d.getUTCMonth()]} ${d.getUTCFullYear()}`; };
/** 'Oct 2026' */
export const fmtMonthYear = (v) => { const d = toDate(v); return `${MONTHS[d.getUTCMonth()]} ${d.getUTCFullYear()}`; };
/** '6 Oct' */
export const fmtDayMonth = (v) => { const d = toDate(v); return `${d.getUTCDate()} ${MONTHS[d.getUTCMonth()]}`; };

/** Add whole months, clamping the day (31 Mar - 6 months = 30 Sep, not 1 Oct). Returns a Date. */
export function addMonths(v, n) {
  const d = toDate(v);
  const y = d.getUTCFullYear(), m = d.getUTCMonth() + n, day = d.getUTCDate();
  const last = new Date(Date.UTC(y, m + 1, 0)).getUTCDate();
  return new Date(Date.UTC(y, m, Math.min(day, last)));
}

/** Fractional calendar months from a to b (negative if b is before a).
 *  Exact at whole-month anchors: monthsBetween('2026-10-06','2027-01-06') === 3. Used only for x positions. */
export function monthsBetween(a, b) {
  const A = toDate(a), B = toDate(b);
  let whole = (B.getUTCFullYear() - A.getUTCFullYear()) * 12 + (B.getUTCMonth() - A.getUTCMonth());
  let anchor = addMonths(A, whole);
  if (B < anchor) { whole -= 1; anchor = addMonths(A, whole); }
  const next = addMonths(A, whole + 1);
  return whole + (B - anchor) / (next - anchor);
}
export const daysBetween = (a, b) => Math.round((toDate(b) - toDate(a)) / DAY);

/** Radar wording: '25 days left' / 'Due today' / '6 days ago' (matches the requirements doc, section 5.3) */
export function relativeFrom(asOf, v) {
  const d = daysBetween(asOf, v);
  if (d === 0) return 'Due today';
  const n = Math.abs(d);
  return d > 0 ? `${n.toLocaleString('en-GB')} day${n === 1 ? '' : 's'} left` : `${n.toLocaleString('en-GB')} day${n === 1 ? '' : 's'} ago`;
}

/* ---------------------------------------------------------------- money */
const GBP0 = new Intl.NumberFormat('en-GB', { style: 'currency', currency: 'GBP', maximumFractionDigits: 0 });

/** Tables / exact figures / aria-labels: £18,900,000 (same as the engine's fmtGBP) */
export const gbpFull = (n) => (n < 0 ? MINUS : '') + GBP0.format(Math.abs(n));

/** Compact: £1.2m, £18.9m, £340k, £9,500. One decimal from £1m, whole £k from £10k, full figure below.
 *  Agrees with the engine's fmtGBPCompact from £1m up and below £100k; between £100k and £1m it keeps
 *  the £k precision (£642k, not £0.6m). Where an acceptance test fixes the string (Overview cards), pass format={fmtGBPCompact}. */
export function gbp(n, { sign = false } = {}) {
  const a = Math.abs(n);
  let s;
  if (a >= 999500) s = '£' + (Math.round(a / 1e5) / 10).toLocaleString('en-GB', { minimumFractionDigits: 1, maximumFractionDigits: 1 }) + 'm';   // integer rounding: 8.35m -> £8.4m (toFixed gives 8.3)
  else if (a >= 10000) { const k = Math.round(a / 1000); s = k >= 1000 ? '£1.0m' : '£' + k + 'k'; }
  else s = '£' + Math.round(a).toLocaleString('en-GB');
  return (n < 0 ? MINUS : sign && n > 0 ? '+' : '') + s;
}

/** The engine's own compact formatter (golden strings such as '£0.6m'). Re-exported here so charts can take it as `format`. */
export const fmtGBPCompact = (x) => {
  const a = Math.abs(x);
  if (a >= 1e5) return '£' + (Math.round(x / 1e5) / 10).toFixed(1) + 'm';
  if (a >= 1e4) return '£' + Math.round(x / 1e3) + 'k';
  return gbpFull(x);
};

/** Axis ticks: £0, £2m, £2.5m, £500k (no trailing .0). */
export function gbpTick(n) {
  const a = Math.abs(n);
  if (a === 0) return '£0';
  if (a >= 1e6) return '£' + +(a / 1e6).toFixed(1) + 'm';
  if (a >= 1e3) return '£' + +(a / 1e3).toFixed(0) + 'k';
  return '£' + a;
}

/** Ratio to percent: pct(0.853) -> '85%'; pct(0.948, 1) -> '94.8%'. */
export const pct = (r, dp = 0) => (r < 0 ? MINUS : '') + Math.abs(r * 100).toFixed(dp) + '%';
/** Percentage-point difference: '+4.2 pts' */
export const pts = (r, dp = 1) => (r < 0 ? MINUS : '+') + Math.abs(r * 100).toFixed(dp) + ' pts';
/** '1 contract', '12 contracts', '1,203 payments' */
export const plural = (n, one, many = one + 's') => `${n.toLocaleString('en-GB')} ${n === 1 ? one : many}`;
/** Axis tick for a ratio: 0.025 -> '2.5%', 0.04 -> '4%', -0.5 -> '-50%' */
export const pctTick = (r) => (r < 0 ? MINUS : '') + +(Math.abs(r) * 100).toFixed(1) + '%';

export const clamp = (x, a, b) => Math.min(b, Math.max(a, x));

/** linear([d0,d1],[r0,r1]) -> f(v); f.invert(y) */
export function linear([d0, d1], [r0, r1]) {
  const k = (r1 - r0) / (d1 - d0 || 1);
  const f = (v) => r0 + (v - d0) * k;
  f.invert = (y) => d0 + (y - r0) / k;
  return f;
}

/** Round up to a "nice" number (1, 2, 2.5, 5 x 10^n). */
export function niceStep(rough, steps = [1, 2, 2.5, 5, 10]) {
  const p = Math.pow(10, Math.floor(Math.log10(rough)));
  const f = rough / p;
  return (steps.find((s) => f <= s) || 10) * p;
}
/** [0, step, 2*step ... >= max] with ~count ticks. Pass steps=[1,2,5,10] to avoid 2.5 steps (percent axes). */
export function niceTicks(max, count = 5, steps) {
  const step = niceStep(max / count, steps);
  const out = [];
  for (let v = 0; v < max + step * 0.999; v += step) out.push(+v.toFixed(10));
  return out;
}

/** Index of the point whose x is closest to px (points sorted ascending). */
export function nearestIndex(xs, px) {
  let lo = 0, hi = xs.length - 1;
  while (hi - lo > 1) { const mid = (lo + hi) >> 1; if (xs[mid] < px) lo = mid; else hi = mid; }
  return Math.abs(xs[lo] - px) <= Math.abs(xs[hi] - px) ? lo : hi;
}

import { useState, useLayoutEffect, useRef, useCallback } from 'react';

/** Width of an element in px, updated on resize. Returns [ref, width]. */
export function useWidth() {
  const ref = useRef(null);
  const [w, setW] = useState(0);
  useLayoutEffect(() => {
    const el = ref.current;
    if (!el) return undefined;
    setW(Math.round(el.getBoundingClientRect().width));
    if (typeof ResizeObserver === 'undefined') return undefined;
    const ro = new ResizeObserver(([e]) => setW(Math.round(e.contentRect.width)));
    ro.observe(el);
    return () => ro.disconnect();
  }, []);
  return [ref, w];
}

/** Arrow-key navigation between interactive marks inside a list/figure.
 *  Spread onto the container: <ul {...useArrowNav('[data-kviz-mark]')}>.  Tab still works as normal. */
export function useArrowNav(selector = '[data-kviz-mark]') {
  const onKeyDown = useCallback((e) => {
    const keys = ['ArrowDown', 'ArrowUp', 'ArrowRight', 'ArrowLeft', 'Home', 'End'];
    if (!keys.includes(e.key)) return;
    const items = Array.from(e.currentTarget.querySelectorAll(selector));
    const i = items.indexOf(document.activeElement);
    if (i < 0) return;
    e.preventDefault();
    const next = e.key === 'Home' ? 0 : e.key === 'End' ? items.length - 1
      : (e.key === 'ArrowDown' || e.key === 'ArrowRight') ? Math.min(items.length - 1, i + 1) : Math.max(0, i - 1);
    items[next].focus();
  }, [selector]);
  return { onKeyDown };
}

// src/components/charts/Tip.jsx
// One accessible tooltip for every chart.
//  - Appears on pointer hover AND on keyboard focus of the mark (same content).
//  - Rendered in a portal with position:fixed, so a Card's overflow:hidden never clips it.
//  - WCAG 1.4.13: dismissible (Esc), hoverable (pointer may move onto it), persistent until dismissed.
//  - It enhances, never gates: the mark's own aria-label carries the same facts, and every chart has a table view.
//  - All strings go through React text nodes (never innerHTML): supplier names are untrusted data.
import { useState, useRef, useCallback, useEffect, useLayoutEffect } from 'react';
import { createPortal } from 'react-dom';
import { clamp } from './scales.js';

const rectOf = (el) => { const r = el.getBoundingClientRect(); return { left: r.left, right: r.right, top: r.top, bottom: r.bottom }; };

export function useChartTip() {
  const [tip, setTip] = useState(null);           // { rect, px, content }
  const timer = useRef(0);
  const keep = useCallback(() => clearTimeout(timer.current), []);
  const hide = useCallback(() => { clearTimeout(timer.current); setTip(null); }, []);
  const hideSoon = useCallback(() => { clearTimeout(timer.current); timer.current = setTimeout(() => setTip(null), 160); }, []);
  const show = useCallback((rect, content, px) => { clearTimeout(timer.current); setTip({ rect, content, px }); }, []);
  const open = !!tip;

  useEffect(() => {
    if (!open) return undefined;
    const onKey = (e) => { if (e.key === 'Escape') hide(); };
    const onDown = (e) => { if (!(e.target.closest && e.target.closest('[data-kviz-mark],.kviz-tip'))) hide(); };
    window.addEventListener('keydown', onKey);
    window.addEventListener('pointerdown', onDown, true);
    window.addEventListener('scroll', hide, true);
    return () => {
      window.removeEventListener('keydown', onKey);
      window.removeEventListener('pointerdown', onDown, true);
      window.removeEventListener('scroll', hide, true);
    };
  }, [open, hide]);

  /** Pointer handlers (hover). Put these on the whole row / mark. */
  const bindPointer = useCallback((content) => ({
    onPointerEnter: (e) => show(rectOf(e.currentTarget), content, e.clientX),
    onPointerMove: (e) => { if (e.pointerType !== 'touch') { const px = e.clientX; setTip((t) => (t ? { ...t, px } : t)); } },
    onPointerLeave: (e) => { if (e.pointerType !== 'touch') hideSoon(); },
  }), [show, hideSoon]);
  /** Focus handlers + the marker attribute. Put these on the FOCUSABLE element (the row's primary link/button).
   *  rowSelector: position the tooltip against the whole row instead of the small link. */
  const bindFocus = useCallback((content, rowSelector) => ({
    'data-kviz-mark': '',
    onFocus: (e) => show(rectOf((rowSelector && e.currentTarget.closest(rowSelector)) || e.currentTarget), content),
    onBlur: hide,
  }), [show, hide]);
  /** Both at once, for a mark that is itself the focusable element (a stacked-bar segment). */
  const bind = useCallback((content) => ({ ...bindPointer(content), ...bindFocus(content) }), [bindPointer, bindFocus]);

  return { tip, bind, bindPointer, bindFocus, show, hide, hideSoon, keep };
}

/** content = { title, sub?, rows?: [{ value, label, color?, glyph?, glyphColor? }], note? } */
export function TipBody({ c }) {
  return (
    <>
      {c.title && <div className="kviz-tip__title">{c.title}</div>}
      {c.sub && <div className="kviz-tip__sub">{c.sub}</div>}
      {c.rows && c.rows.length > 0 && (
        <div className="kviz-tip__rows">
          {c.rows.map((r, i) => (
            <div className="kviz-tip__row" key={i}>
              <span className="kviz-tip__key" style={r.color ? { background: r.color } : undefined} aria-hidden="true" />
              <span className="kviz-tip__val">
                {r.glyph && <i className={'fa-solid fa-' + r.glyph} style={{ color: r.glyphColor, marginRight: 6 }} aria-hidden="true" />}
                {r.value}
              </span>
              <span className="kviz-tip__lab">{r.label}</span>
            </div>
          ))}
        </div>
      )}
      {c.note && <div className="kviz-tip__note">{c.note}</div>}
    </>
  );
}

export function ChartTip({ api }) {
  const { tip, keep, hideSoon } = api;
  const ref = useRef(null);
  const [pos, setPos] = useState(null);
  useLayoutEffect(() => {
    if (!tip || !ref.current) { setPos(null); return; }
    const el = ref.current, w = el.offsetWidth, h = el.offsetHeight;
    const r = tip.rect, vw = document.documentElement.clientWidth, vh = window.innerHeight;
    const cx = tip.px == null ? (r.left + r.right) / 2 : clamp(tip.px, r.left, r.right);
    const left = clamp(cx - w / 2, 8, Math.max(8, vw - w - 8));
    let top = r.top - h - 10;
    if (top < 8) top = Math.min(r.bottom + 10, vh - h - 8);   // flip below when there is no room above
    setPos({ left, top });
  }, [tip]);
  if (!tip) return null;
  return createPortal(
    <div ref={ref} className="kviz-tip" role="tooltip"
      style={{ left: pos ? pos.left : 0, top: pos ? pos.top : 0, visibility: pos ? 'visible' : 'hidden' }}
      onPointerEnter={keep} onPointerLeave={hideSoon}>
      <TipBody c={tip.content} />
    </div>,
    document.body,
  );
}

export function Dumbbell({ rows, tolerance = 0.01, axisMin = -0.05, axisMax = 0.3, getHref, onOpen }) {
  const tip = useChartTip();
  const nav = useArrowNav();
  const data = useMemo(() => rows.map((r) => {
    const excess = r.actual - r.cap;

    const state = flagged ? UPLIFT_STATES.flag : excess > 0 ? UPLIFT_STATES.tolerance : UPLIFT_STATES.ok;
    return { ...r, excess, state };
  }).sort((a, b) => b.excess - a.excess), [rows, tolerance]);

  // The axis is clipped to [axisMin, axisMax] so one outlier (payments fell 54%) cannot flatten the 0-12% region where the decisions are.
  const vals = data.flatMap((r) => [r.cap, r.actual]);

          const href = getHref ? getHref(r) : undefined;
          const Tag = href ? 'a' : 'button';
          const lo2 = Math.min(r.cap, r.actual), hi2 = Math.max(r.cap, r.actual);

            ],
            note: 'Payments also move with volume and scope. Check the invoices before you act.',
          };
          return (

                  <span className="kviz-db__link" style={{ left: P(lo2) + '%', width: (P(hi2) - P(lo2)) + '%', background: s.key === 'ok' ? 'var(--viz-ink-2)' : s.color, opacity: s.key === 'ok' ? 0.5 : 1 }} />

/** Ranked flags -> OpportunityList items. clauseFor(flag) -> { label: 'View clause, page 23', href } (from the provenance records). */

/** Attributed payments of one contract -> CumulativeLine series (month-end points).
 *  The line starts at 0 on the LATER of the contract start and the first day of the spend files (spendFrom = council.spendDataFrom),
 *  so a contract that began before the files do not show an invented ramp; label such figures "At least" (R39). */
export function cumulativeSeries(attributed, contract, spendFrom) {
  const byMonth = new Map();
  attributed.filter((a) => a.contractId === contract.id).forEach((a) => {
    const k = a.payment.date.slice(0, 7);
    byMonth.set(k, (byMonth.get(k) || 0) + a.payment.amountGBP);
  });
  const first = spendFrom && spendFrom > contract.startDate ? spendFrom : contract.startDate;
  const out = [{ date: first, pay: 0, cum: 0 }];
  let cum = 0;
  [...byMonth.keys()].sort().forEach((k) => {
    const [y, m] = k.split('-').map(Number);
    const end = iso(new Date(Date.UTC(y, m, 0)));
    cum += byMonth.get(k);
    out.push({ date: end, pay: Math.round(byMonth.get(k)), cum: Math.round(cum) });
  });
  return out;
}
